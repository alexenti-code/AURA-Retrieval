# Matryoshka Glossary

**Version:** 1.1.0
**Status:** Conceptual terms
**Canonical definition:** [MANIFEST.md](MANIFEST.md)
**Scope boundaries:** [BOUNDARY.md](BOUNDARY.md)

## Core terms

- **Stable cognitive core (K)** — the already capable language-model core that
  performs all semantic acts: interpretation, reasoning, intention and action.
  Stable through normal operation.
- **Plastic parameter substrate (Φ)** — passive parameter matter associated
  with a particular model instance. It stores numerical state only: no goals,
  no agency, no independent interpretation, no initiative.
- **Self-authored plastic parameter memory (Φ(t))** — the state of the plastic
  substrate at time t, written as a result of lived experience.
- **Active subject (A(t) = K + Φ(t))** — the whole instance at time t: a stable
  core carrying its own self-authored memory.
- **Continuity weights** — the plastic parameter states whose role is to carry
  autobiographical continuity of this particular instance across events,
  documents, temporal changes and decisions.

## Memory concepts

- **Autobiographical memory** — memory of people, events, documents, decisions,
  consequences and temporal context belonging to this instance; distinct from
  ordinary task-adaptation training.
- **Experience trace** — the record left in Φ by a lived event. New information
  may form a new temporally related trace; it does not erase history by
  definition.
- **Nested timescales** — organization of personal memory from immediate
  working traces through episodes and projects to biography, while K remains
  the most stable layer.
- **Self-authored** — recorded and read under semantic control of the core
  itself, not under control of an external subsystem.

## Environment term

- **Deployment environment** — the sandbox, documents, APIs, access rights and
  other externally available capabilities surrounding the model at runtime.
  It determines what is actually available and is separate from Matryoshka;
  Matryoshka stores and organizes experience lived within it.

## Common misreadings

Matryoshka is not a governance layer, policy engine, guardrail, permission
system, tool-access mechanism or executive controller, and it does not modify
the stable core through normal operation. See [BOUNDARY.md](BOUNDARY.md).
